AGENDA PLANNER — INSTALAÇÃO E EXECUÇÃO
Atualizado em 05/09/2026

1. FERRAMENTAS
Use Node 22.22.3 (.nvmrc) e npm 12.0.2. A instalação é independente nas
pastas server e mobile. Não rode npm install na raiz.

  cd server
  npm ci --ignore-scripts
  npm test

Em outro terminal, a partir da raiz:
  cd mobile
  npm ci --ignore-scripts
  npm test

Os .npmrc bloqueiam lifecycle scripts de dependências e preservam o modo
legacy-peer-deps usado para gerar os lockfiles. Não use audit fix --force.
Os scripts explícitos npm test/npm start continuam disponíveis.

2. API LOCAL
Copie server/.env.example para server/.env. Nunca versionar .env.
Configure DB_TYPE=mongo ou mysql e credenciais do ambiente de desenvolvimento.
Use um banco descartável para testes manuais.
SUPABASE_URL é obrigatória e deve apontar ao mesmo projeto usado no mobile.
Com chaves assimétricas, deixe SUPABASE_JWT_SECRET vazio: a API usa JWKS.
Para HS256 legado, use o JWT Secret real desse projeto (mínimo 32 caracteres),
não uma chave inventada. Placeholders são recusados. JWT_SECRET e
JWT_REFRESH_SECRET não são usados por esta aplicação.

Na pasta server:
  npm start

O endpoint /api/health responde sem token. Os demais dados exigem access token
do Supabase com issuer do projeto, audiência authenticated, UUID sub e exp.
O módulo exporta Express sem abrir porta nem conectar banco quando importado
pelos testes.

3. BANCO
Mongo local: MONGO_URI=mongodb://localhost:27017/agenda.
Mongo remoto: utilize TLS (mongodb+srv quando suportado), usuário readWrite
apenas no banco da aplicação e allowlist de IPs da infraestrutura. Não libere
0.0.0.0/0 como padrão.

MySQL local: configure MYSQL_HOST/PORT/USER/PASSWORD/DATABASE. Em development
ou test, sync() cria tabelas ausentes; não usa alter nem force. Em produção,
a API não modifica o schema. Prepare/migre o schema previamente com usuário
administrativo separado, backup e validação em staging. Uma base existente
mantém o schema anterior; adicionar índices deve ser uma migração revisada.
Use usuário de runtime restrito a SELECT/INSERT/UPDATE/DELETE nas tabelas do app.
MySQL remoto: MYSQL_SSL=true; se necessário MYSQL_SSL_CA com a CA PEM do
provedor (aceita \n). A verificação do certificado permanece ativa.
Não use NODE_ENV=development contra o banco de produção para criar tabelas.

4. MOBILE
mobile/supabase.js contém a URL e anon key públicas do projeto. Se usar outro
projeto, altere ambos e AUTH_STORAGE_KEY; não coloque service_role no cliente.
Configure EXPO_PUBLIC_API_URL com a URL HTTPS da sua API em mobile/.env.
Sem essa variável, config.js mantém a URL Railway já usada pelo projeto.
Variáveis EXPO_PUBLIC são incorporadas ao bundle e não guardam segredos.
Para desenvolvimento com celular, exponha a API de teste por HTTPS confiável
ou proxy TLS de desenvolvimento; não remova a validação HTTPS do cliente.

Na pasta mobile:
  npm start
  node node_modules/expo/bin/cli export --platform android --output-dir dist --no-minify

SecureStore, FileSystem, notificações e áudio exigem validar um build nativo
compatível com Expo 54. O export gera JS/Hermes e assets, não um APK.
A nova configuração de plugins/permissões exige recompilar o aplicativo.
Confira em aparelho a migração da sessão, logout, lembretes, galeria e slider.

5. PRODUÇÃO
NODE_ENV=production. HTTPS na entrada e TLS no banco remoto.
ALLOWED_ORIGINS: origens web exatas separadas por vírgula, nunca '*'.
Apps nativos não dependem de CORS para autenticação.
TRUST_PROXY: deixe vazio até conhecer os IPs/CIDRs dos proxies confiáveis;
configure a lista real e impeça acesso direto não autorizado ao Node.
Sem isso, o rate limiter pode agrupar todos os usuários pelo IP do proxy.
O limiter é por processo (100 requisições/15 minutos); várias réplicas precisam
de armazenamento compartilhado ou limite na borda. A fila preserva 429 para
nova tentativa ao reconectar, retomar o app ou recarregar.
Configure no Supabase confirmação de e-mail, limites de login/OTP e template
recovery com código correspondente ao fluxo da interface. Verifique backups,
RLS aplicável e retenção no ambiente; o código local não comprova esses controles.

6. AUDITORIA
Na pasta server ou mobile:
  node ../scripts/audit-dependencies.cjs

A triagem identifica advisories específicos e tem validade até 05/10/2026.
Não oculta o resultado npm audit. Consulte review/CORRECOES.md.
